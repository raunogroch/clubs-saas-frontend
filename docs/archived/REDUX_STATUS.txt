┌─ LISKOV SUBSTITUTION PRINCIPLE (LSP)
│
├─ ✅ useAuth() reemplaza AuthContext
│  │ • Mismo interfaz: { user, token, isAuthenticated, logout }
│  │ • Uso idéntico: const { user } = useAuth()
│  └─ Componentes NO notan el cambio
│
├─ ✅ createBaseQueryWithAuth() reemplaza fetchBaseQuery()
│  │ • Mismo interfaz: (baseUrl) => BaseQuery
│  │ • Firma compatible: (headers, { getState }) => headers
│  └─ RTK Query NO necesita cambios
│
└─ ✅ storage.ts reemplaza localStorage
   │ • Mismo interfaz: { getItem, setItem, removeItem, clear }
   │ • Retorna Promises: Promise<string|null>
   └─ redux-persist NO sabe sobre fallback


┌─ INTERFACE SEGREGATION PRINCIPLE (ISP)
│
├─ ✅ UseAuthReturn - interfaz específica
│  │ • { user, token, isAuthenticated, isLoading, error, logout }
│  │ • Solo lo necesario
│  └─ Componentes NO usan propiedades innecesarias
│
├─ ✅ User type - separado por contexto
│  │ • core/types/User.ts - definición centralizada
│  │ • features/auth/authApi.ts - tipos de request/response
│  └─ Cada contexto ve solo lo que necesita
│
└─ ✅ RTK Query endpoints - específicos
   │ • login mutation: LoginRequest → LoginResponse
   │ • validateToken query: void → { valid: boolean }
   └─ Cada endpoint tiene su tipo


┌─ DEPENDENCY INVERSION PRINCIPLE (DIP)
│
├─ ✅ Componentes dependen de hooks (abstracción)
│  │ import { useAuth } from '@/core/hooks'
│  │ ❌ NO: import Redux directly
│  └─ Cambiar Redux a Context sin modificar componentes
│
├─ ✅ APIs dependen de baseQueryWithAuth (abstracción)
│  │ createApi({ baseQuery: createBaseQueryWithAuth(...) })
│  │ ❌ NO: acceder a localStorage directamente
│  └─ Cambiar a OAuth sin modificar todos los APIs
│
└─ ✅ Redux depende de storage (abstracción)
   │ redux-persist({ storage })
   │ ❌ NO: asumir window.localStorage existe

🔄 FLUJO DE PERSISTENCIA
═══════════════════════════════════════════════════════════════════════════════

LOGIN FLOW:
─────────────────────────────────────────────────────────────────────────────

  User Input (username, password)
          ↓
  useAuthManager().login(credentials)
          ↓
  RTK Query: POST /auth/login
          ↓
  Server Response: { user: User, token: "jwt..." }
          ↓
  dispatch(loginSuccess(result))
          ↓
  Redux State Updated:
  • state.auth.token = "jwt..."
  • state.auth.user = User
  • state.auth.isAuthenticated = true
          ↓
  redux-persist Detects Change
          ↓
  storage.setItem('persist:root', serialized)
          ↓
  localStorage['persist:root'] Updated
          ↓
  ✅ TOKEN PERSISTED


RELOAD FLOW:
─────────────────────────────────────────────────────────────────────────────

  Page Reload (F5)
          ↓
  Redux Store Initializes (initialState)
          ↓
  Provider mounted → PersistGate mounted
          ↓
  PersistGate: persistor.rehydrate()
          ↓
  redux-persist: storage.getItem('persist:root')
          ↓
  storage.getItem:
  • Try: window.localStorage.getItem('persist:root')
  • Catch: return inMemory['persist:root']
          ↓
  Redux State Restored:
  • state.auth.token = "jwt..."
  • state.auth.user = User
  • state.auth.isAuthenticated = true
          ↓
  PersistGate: loading={null} → Render Components
          ↓
  Components Access useAuth():
  • const { user, token } = useAuth()
  • ✅ TOKEN AVAILABLE
          ↓
  useGetAssignmentsQuery() Fires:
  • baseQueryWithAuth prepareHeaders
  • { getState() } → getState().auth.token
  • Authorization: Bearer jwt...
          ↓
  ✅ AUTO-LOGIN WORKS, NO USER ACTION NEEDED


REQUEST FLOW:
─────────────────────────────────────────────────────────────────────────────

  Component: useGetAssignmentsQuery()
          ↓
  RTK Query: GET /assignments
          ↓
  createBaseQueryWithAuth prepareHeaders:
  • const state = getState() as RootState
  • const token = state.auth.token
  • if (token) headers.set('authorization', `Bearer ${token}`)
          ↓
  ✅ TOKEN FROM REDUX, NOT LOCALSTORAGE
          ↓
  Fetch with Headers:
  • Authorization: Bearer jwt...
  • Content-Type: application/json
          ↓
  Server Response (200 OK):
  • { data: Assignment[], meta: { ... } }
          ↓
  RTK Query Cache Updated
          ↓
  Component Re-renders
  • ✅ DATA DISPLAYED


LOGOUT FLOW:
─────────────────────────────────────────────────────────────────────────────

  Component: useAuth().logout()
          ↓
  dispatch(logout())
          ↓
  Redux State Updated:
  • state.auth.user = null
  • state.auth.token = null
  • state.auth.isAuthenticated = false
          ↓
  redux-persist Detects Change
          ↓
  storage.removeItem('persist:root')
  • window.localStorage.removeItem('persist:root')
  • delete inMemory['persist:root']
          ↓
  ✅ TOKEN CLEARED FROM STORAGE
          ↓
  Components Re-render:
  • useAuth().isAuthenticated = false
  • <ProtectedRoute /> → redirect to /login
          ↓
  ✅ LOGOUT COMPLETE


🔐 SEGURIDAD & SINCRONIZACIÓN
═══════════════════════════════════════════════════════════════════════════════

ONE SOURCE OF TRUTH:
┌──────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  Redux Store (State)                                                │
│  ├─ state.auth.token = "jwt..."                                     │
│  ├─ state.auth.user = { id, name, roles }                           │
│  └─ state.auth.isAuthenticated = true                               │
│                                                                      │
│              ↕ (redux-persist syncs both directions)                │
│                                                                      │
│  localStorage (Persistence)                                         │
│  └─ persist:root = "{ auth: { token: "jwt...", ... } }"            │
│                                                                      │
│  ✅ SYNCHRONIZED: Any change in Redux → localStorage updated        │
│  ✅ SYNCHRONIZED: Page reload → localStorage restored to Redux      │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

FALLBACK MECHANISM:
┌──────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  storage.setItem(key, value):                                       │
│  ├─ Try: window.localStorage.setItem(key, value)                    │
│  ├─ Catch: inMemory[key] = value (fallback)                         │
│  └─ Result: Always succeeds, never throws                           │
│                                                                      │
│  storage.getItem(key):                                              │
│  ├─ Try: return window.localStorage.getItem(key)                    │
│  ├─ Catch: return inMemory[key] (fallback)                          │
│  └─ Result: Always returns value or null, never throws             │
│                                                                      │
│  ✅ WORKS IN: browser, Node.js (SSR), iframe, tests                │
│  ✅ GRACEFUL DEGRADATION: If localStorage fails, uses memory       │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

TOKEN OBTENTION ORDER:
┌──────────────────────────────────────────────────────────────────────┐
│                                                                      │
│  createBaseQueryWithAuth prepareHeaders:                            │
│                                                                      │
│  1. { getState } from RTK Query                                     │
│  2. const state = getState() as RootState                           │
│  3. const token = state.auth.token                                  │
│  4. if (token) headers.set('Authorization', Bearer ${token})        │
│                                                                      │
│  ✅ Token is ALWAYS from Redux store                                │
│  ✅ NEVER reads localStorage directly in requests                   │
│  ✅ localStorage is just persistence, not request source            │
│                                                                      │
└──────────────────────────────────────────────────────────────────────┘

⚡ VENTAJAS DEL NUEVO SISTEMA
═══════════════════════════════════════════════════════════════════════════════

1. Una sola fuente de verdad
   • Token en Redux store
   • localStorage es solo cache
   • Actualizaciones sincronizadas automáticamente

2. Sincronización automática  
   • Redux actualiza → redux-persist guarda
   • Page reload → redux-persist restaura
   • Componentes siempre ven estado actual

3. Seguridad mejorada
   • Token no está esparcido en múltiples lugares
   • localStorage tiene fallback seguro
   • RTK Query obtiene token actualizando Redux

4. Mantenibilidad
   • Cambios futuros solo en baseQueryWithAuth
   • Todos los APIs se benefician
   • Fácil de testear

5. Escalabilidad
   • Agregar nuevas APIs: solo usar createBaseQueryWithAuth
   • Cambiar auth strategy: solo modificar baseQueryWithAuth
   • Sin breaking changes
